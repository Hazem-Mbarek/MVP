Most likely causes, roughly in order of likelihood:

Root cause #2 — no graceful degradation when a tool call fails

This is the second, compounding bug, and it's why some failures show helpful text ("not found in knowledge base") while others show nothing at all. Compare case 9/10/15 (explicit, readable failure text) against case 3/5/11/12/17/19 (blank). Same underlying tool failure, wildly different agent behavior. That inconsistency means the failure mode itself is unhandled — sometimes the model narrates its way to a coverage-gap message, sometimes the broken tool call (or a downstream synthesis step depending on it) just crashes the turn with no output at all.

This matters independently of fixing bug #1, because it explains why the decompose cases are disproportionately blank (3, 12, 17, 19) — decomposition means multiple tool calls, and if any one of them fails silently, the synthesis step has nothing to work with and produces nothing back.

Fix (belongs in the routing policy doc): add an explicit rule — a tool call returning an error or empty result must always produce an explicit coverage-gap statement in the final answer, never a blank turn. I'd phrase it as a hard constraint, something like:

<rule>any_tool_call_error_or_empty -> agent must still produce output text stating the gap; blank output is never valid</rule>

This alone should convert most of the 7 blank cases into at least a legible "not found" response — not a full fix, but it stops the silent failures while bug #1 gets root-caused.

Root cause #3 — timeout (Decompose 2) is very likely downstream of #1 and #2

"Compare CIF vs FCA insurance obligations" needs compare_incoterms. If that call is failing in a way that triggers retries (rather than failing fast), and the agent keeps re-attempting it inside a decompose loop before giving up, that's a plausible mechanism for a 60s timeout on exactly the kind of question that needs the broken tool. Worth checking whether there's retry logic around tool calls — if compare_incoterms is fixed, this may resolve on its own; if it doesn't, you have a separate retry/loop bug to chase.
